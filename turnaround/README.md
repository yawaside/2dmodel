# ChibiVT — ракурсы и раскадровка для подготовки Live2D

## Что сделано

- **8 кадров полного роста**: спереди, две передние ¾, два профиля, две задние ¾ и сзади.
- **9 референсов головы**: целевая сетка `ParamAngleX / ParamAngleY = −30, 0, +30`.
- PNG с прозрачным фоном для каждого полного ракурса, одинаковый холст **768 × 1024**, линия стоп `y=974`, опорная точка `[384, 974]`.
- Контактные листы с подписями, двухстраничный PDF, 8-кадровый GIF (4 секунды), спрайт-лист 4 × 2, CSV таймлайн и JSON манифест.
- **PSD референсов**: каждый ракурс — отдельный подписанный слой в группе `BODY_REFERENCES`; головы — отдельная скрытая группа. По умолчанию виден только фронтальный кадр. Это **не PSD с нарезанными частями тела**.
- Браузерный просмотрщик без Cubism Core: выбор кадра, покадровое воспроизведение, предыдущий кадр-подложка, сетка, экспорт и локальный чек-лист подготовки слоёв.

## Важные границы результата

Это **AI-референс-пакет для художника/риггера**, а не точная 3D-реконструкция и не новый 360° Live2D-риг. Существующие `chibi_soldier_rig.psd`, `psd_layers/`, `dist/ChibiVT/` и скрипты сборки `.moc3` не изменены.

Исходный `cutout.png` показывает только переднюю верхнюю часть персонажа. Спина, брюки, кисти и ботинки — предложенное продолжение дизайна. Между AI-рисунками есть отличия в экипировке и пропорциях; их нужно согласовать, а не импортировать как финальную нарезку.

**Кадры 45°, 135° и 270° — зеркальные черновики** соответствующих рисунков противоположной стороны. Они явно отмечены в просмотрщике, PSD, CSV, JSON и контактном листе. Зеркалирование — не достоверное восстановление скрытой стороны. В частности, на исходном фронте микрофон находится справа для зрителя (слева у персонажа): после отражения это нужно исправить. Проверить сторону микрофона/наушников, узел платка, порядок подсумков и рисунок камуфляжа на **всех** ракурсах, в том числе немирроренных.

Размер фигур в сгенерированных исходных листах — около 660 px по высоте. PNG 768 × 1024 получены выравниванием и увеличением этих рисунков, не добавлением детализации. Автоматически удалённый светлый фон требует проверки краёв перед чистовой работой. Для финальной Live2D-нарезки желательно перерисовать утверждённый дизайн в большем разрешении.

Угол раскадровки — **условный азимут камеры**, не значение `ParamAngleX` и не измеренный поворот: `0°` — спереди, `90°` — профиль лицом влево на экране, `180°` — сзади, `270°` — профиль лицом вправо. Метки X/Y у головы — целевые ключи; AI-перспектива приблизительная и требует корректировки, особенно крайние наклоны. 8 кадров не дают плавного 3D-вращения: GIF и просмотрщик показывают именно последовательность опорных кадров.

## Файлы

В репозитории готовый набор лежит в `turnaround/pack/`. В ZIP содержимое лежит в `ChibiVT_turnaround/`.

| Файл | Назначение |
|---|---|
| `turnaround_board.png` | Обзор 8 ракурсов с маркировкой зеркальных черновиков |
| `head_board.png` | 9 референсов головы с целевыми ключами X/Y |
| `frames/*.png` | Отдельные RGBA кадры полного роста, 768 × 1024 |
| `heads/*.png` | Кадры головы, 512 × 512, **с непрозрачным фоном** |
| `body_sprite_sheet.png` | 3072 × 2048, 4 столбца × 2 строки, порядок слева направо |
| `turnaround.gif` | Покадровый оборот: 8 × 500 мс, замкнутый цикл |
| `storyboard.csv` | Номер, время, угол, файл, статус и опорная точка |
| `manifest.json` | Метаданные, исходные кропы/отражения, SHA-256 исходных листов |
| `reference_boards.pdf` | Листы ракурсов и головы для печати |
| `ChibiVT_turnaround_references.psd` | Слои **целых кадров**; создаётся с `--psd` |
| `ChibiVT_turnaround_pack.zip` | Полный пакет |

`turnaround/source/` содержит AI-сгенерированные исходные листы. В них могут быть ошибочные подписи, добавленные генератором. Скрипт их обрезает и использует разметку, проверенную по рисункам, а не по исходным надписям.

## Как перейти к Live2D

1. **Утвердить дизайн.** Свести пропорции головы/тела, высоту плеч и стоп; уточнить заднюю экипировку. Исправить асимметрию трёх зеркальных черновиков и остальных AI-видов.
2. **Нарезать выбранный рабочий ракурс.** Не импортировать весь контактный лист как одну ArtMesh. В Photoshop/Krita/Clip Studio подготовить прозрачный RGB/8-bit PSD с единым размером холста и отдельными частями. Лево/право в названиях частей — стороны самого персонажа.
3. **Дорисовать перекрытые области**: лицо под глазами/волосами/козырьком, шея под платком, тело под руками и жилетом. Оставить запас для деформаций; не ограничиваться обрезкой видимых пикселей.
4. **Импортировать в Cubism Editor**, задать меши и иерархию деформеров `Root → Body → Neck → Head`; гарнитура следует за головой, хвосты платка — отдельные деформеры.
5. Для обычного фронтального трекинга выставить `ParamAngleX/Y = −30, 0, +30` по сетке головы, затем согласовать четыре угловых состояния X/Y; добавить крен Z. Числа — целевые параметры рига, не геометрические замеры рисунков.
6. Отдельно подготовить и настроить `ParamEyeLOpen/ROpen`, `ParamEyeBallX/Y`, `ParamMouthOpenY`, `ParamMouthForm`. Существующие `psd_layers/` могут служить исходником выражений, но их координаты относятся к старому фронтальному арту 1024 × 1024: их нельзя напрямую вставить в новую фигуру без подгонки.
7. **Полный оборот** потребует отдельных комплектов частей для профиля/спины и управления их видимостью и порядком отрисовки. Не растягивать исходный фронт параметром до ±180°. Использовать отдельный пользовательский параметр (например, `ParamTurnaround`) или отдельные модели и самостоятельно связать переключение с приложением.
8. Проверить края, стыки, моргание, рот, крайние углы, смешивание X/Y и физику. Только затем экспортировать `.moc3` и протестировать в VTube Studio. Этот пакет не выполняет шаги 2–8 автоматически.

### Рекомендуемая структура чистового PSD

```text
Root
├── Hair_Back
├── Body
│   ├── Torso_Base                   # дорисован под жилетом/руками
│   ├── Vest_Back / Vest_Front
│   ├── Straps / Pouches             # подвижные элементы отдельно
│   ├── Arm_L / Forearm_L / Hand_L
│   ├── Arm_R / Forearm_R / Hand_R
│   ├── Leg_L / Boot_L
│   └── Leg_R / Boot_R
├── Neck_Base
├── Scarf_Base / Scarf_Knot / Scarf_Tail_L / Scarf_Tail_R
├── Head
│   ├── Face_Base                   # без нарисованных глаз и рта
│   ├── Ear_L / Ear_R
│   ├── Eye_L / Eye_R                # белок, радужка, блики, верхнее/нижнее веко
│   ├── Brow_L / Brow_R
│   ├── Mouth_Inside / Teeth / Tongue / Lip_Upper / Lip_Lower
│   ├── Hair_Front
│   ├── Cap_Crown / Cap_Brim / Cap_Star
│   └── Headset_L / Headset_R / Headband / Mic_Arm / Mic_Tip
└── References                     # скрытая группа, не экспортировать в риг
```

Для вида сзади подготовить собственные `Hair_Back`, заднюю панель кепки, жилет и платок; скрытые глаза/рот не должны оставаться видимыми. Порядок отрисовки деталей меняется в зависимости от ракурса.

## Пересборка и запуск

Из корня репозитория:

```bash
pip install -r requirements-turnaround.txt
python3 tools/build_turnaround.py --psd
python3 -m unittest discover -s tests -v
python3 tools/serve.py . 8000
# /turnaround/ — новый просмотрщик; /preview/ — прежний Cubism-предпросмотр
```

Скрипт работает офлайн с сохранёнными листами и не вызывает AI/API. Для нового персонажа нужно сначала создать и согласовать новые исходные изображения и поправить `VIEWS`/кропы в скрипте. Без `--psd` библиотека psd-tools не обязательна. Выходной каталог можно задать `--output /путь/к/каталогу`.

Чек-лист в просмотрщике хранится только в `localStorage` этого браузера и не означает, что слои автоматически созданы. Кнопка экспорта сохраняет текущее состояние в JSON.

## Права

Новые рисунки созданы с помощью AI по исходному арту проекта. Используйте их в рамках ваших прав на исходник. Библиотека Cubism Core не включена и для просмотра этого пакета не требуется.
